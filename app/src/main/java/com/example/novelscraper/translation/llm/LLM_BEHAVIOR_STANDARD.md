# LLM翻訳 振る舞いメモ（必要時のみ読む）

実装ではなく振る舞いの記録。作業ルールは同フォルダ`AGENTS.md`、詳細手順は`docs/handoff_llm_rebuild_plan.md`。
数値（サイズ比・件数・閾値）はコード定数・設定画面が正本。ここに複写しない。

## 流れ

1. フォルダ選択 → 開始 (`ui/LlmTranslationPanel`)
2. 物理分割ON時：親直下の生テキストを`分割済み/<小説名>/part_*.txt`に事前分割 (`common/NovelPhysicalSplitter`)
3. 言語判定 (`pipeline/LanguageDetector`)＋`.lang_cache`があれば再利用
4. 辞書ON時のみ人名辞書生成 (`pipeline/NovelDictionaryGenerator`)。失敗時はフォルダ全体スキップ
5. 並列ワーカー起動 (`engine/LlmTranslationEngine`)。1ワーカーがGeminiキー1本を専有
6. ファイルごとに3経路へ分岐：
   - 小 → 後続と束ねてバッチ翻訳 (`pipeline/BatchTranslator`、`<doc>/<trans>`タグ形式。JSON Schema時はJSON)。失敗分のみ単体にフォールバック
   - 大 → チャンク分割して順次翻訳 (`pipeline/LargeFileTranslator`、`.parts_*`作業所)。直前訳文末尾のみ文脈注入
   - 単体 → 1件ずつ翻訳
7. 全経路で品質検証 (`pipeline/TranslationQualityValidator`＋`CompletionMarkerHelper`：単体・大ファイルは`[SRC_END]`、バッチは閉じタグ)。NGは次プロンプト/次モデルへ
8. 成功分のみ`翻訳完了_LLM/<元名>`に保存

## 成功・失敗・中断時の扱い

- 成功：出力フォルダに同名ファイル。次回はスキップ
- 真性失敗（全モデル・全プロンプトNG）：`ファイル名.failed`を保存。次回はスキップ（手動削除で再試行）
- チャンク失敗：親直下に`.failed`は作らず`out/chunk_N.failed`のみ記録。`.parts_*`を残して次回レジューム
- 中断（停止ボタン）：`.failed`を作らず中間状態を保持。次回レジューム可能
- 空ファイル：空出力を作って完了扱い
- 0バイト破損：未完了扱いとして警告ログを出し再処理

## 決定事項（動作の約束。2026-09 追加）

- 辞書必須（辞書なし翻訳はしない）
  - フォルダ毎に辞書を先に作り、失敗時はそのフォルダを翻訳せずスキップする
  - 辞書が作れる間は全体を続け、辞書モデル枠の全滅（または翻訳モデル枠の全滅）で初めて全体を中止する。一時的失敗では止めず次フォルダへ進む
- APIキー枯渇時は分割だけが残って動くことはない
  - 分割の全入口（開始前・フォルダ先頭・分割連鎖先頭）に枯渇チェックがあり、枯渇時は分割・辞書・翻訳のいずれも行わない
  - 前提：キー分散ローテーションON（既定）。OFF時は翻訳側の枯渇がプールに伝わらないため、辞書起因の枯渇のみ中止対象になる

- APIキー枯渇時はLLM翻訳全体を停止する（分割のみの実施なし）
  - 開始前：登録モデルに対応するプロバイダーのキーが1つもなければ、分割・辞書・ワーカーの全てを行わず中止
  - 枯渇管理は（キー×モデル）ペア単位（Googleの枠はモデル別のため）。同一キーでも他モデル枠が生きていれば使い続ける
  - フォルダ毎：翻訳モデル全滅（全モデル×全キーがRPD枯渇）＋非Gemini代替なし、または辞書モデル（抽出＋マージ）全滅なら、分割・辞書・翻訳を行わず全体中止。辞書なし翻訳は禁止。RPM一時制限のみは継続
  - 辞書検知の429もモデル名付きで共有プールへ報告するため、辞書起因の枯渇も中止判定に反映される
  - 中止時は進行中ファイルに `.failed` を作らない（次回再開可能にする）
- 品質エラー（生成停止・プロンプト拒否・セーフティ等）は全モデル・全プロンプト全滅後に `.failed` を作る。次回はスキップされる。設定エラーのみ全滅時は作らない
- 辞書の失敗は種別で振り分ける
  - 確定的失敗（コンテンツブロック等。同一内容・同一モデルでは治らない）は即切り上げて除外し、1件以上の成功があれば成功分だけで部分マージして辞書確定する
  - 一時的失敗（429・通信エラー）混じり・成功ゼロの場合は辞書保留→フォルダ翻訳スキップ→次回再開（従来の不完全マージ防止を限定継承）
- 辞書バッチキャッシュは番号と内容の対応を `manifest.json`（SHA-256）で検証する。不一致のみ再取得。manifestなし旧版は信頼して移行時の全再生成を避ける
- 全件翻訳済みフォルダは早期スキップする（出力一覧キャッシュで完了数==総数なら、言語検出・辞書生成・ワーカー起動なし。`.failed` は完了扱い、`.parts_*` 残存は未完了扱い）
- 物理分割時は生ファイルを二重読みしない。取込済みテキストを `onIngestedText` で使い回して言語検出する（既存分割時はパート側再検出に委ねる）
- 辞書の thinkingLevel は設定画面で変更できる（Geminiのみ。未指定＝モデル既定が既定値）
- 対応モデル：`gemini-3.8-flash`（Stable。MINIMAL未対応）と `gemini-3-flash-preview`（Preview。安定版 `gemini-3-flash` は存在しない）。新規モデルは temperature 未送信。thinking可否の判定は `supportsThinkingLevel` に一本化
- 効果のない設定は表示しない（表示＝変更が反映される）。Gemma系は thinking 系を受け付けず送信時400になる報告があるため、thinking パラメータを送らず、翻訳・辞書の設定UIにも思考欄を出さない。判定は `thinkingSupported` に一本化

## 確定値

- サイズ比・例注入件数等の数値は`LlmTranslationConfig`・`TranslationQualityValidator`の定数が正本
- APIキー: 同梱キー維持（削除しない）
- `.failed`: 自動再試行なし、手動削除運用

## やらないこと

- 自動再試行、`.failed`の自動消去
- 中断時の`.failed`作成
- チャンクへの原文二重注入（訳文末尾に一本化）
