# NovelScraper2 — 登場人物辞書・対応表の動作仕様

本書は、LLM翻訳（v2エンジン）における **登場人物辞書（人物対応表）** の振る舞いをまとめた技術・運用解説です。
生成→添付→検証→推敲の各段階で何が起きるか、動作の例で説明します。

なお数値（文字数・件数・閾値）はコード定数・設定画面が正本であり、本書の数値はすべて理解用の例です。ここに複写された数値を正として実装しないでください。

## 1. 全体像（4段階）

1. **生成**：小説全体を走査し、人物名と日本語読み・人物メモの辞書を作ります（初回のみ・次回から再利用）。
2. **添付**：章ごとに登場人物だけを絞り、翻訳指示に付けます（71名登録でも章に関係する10名前後）。
3. **検証**：訳文に日本語読みがあるか確かめます。なければ次の指示文で再送します。
4. **推敲**：on時は原文＋初回訳文＋対応表で磨き直し、検査通過分だけ採用します。

```
[小説フォルダ]
 └─ dictionary.json   ← 完成した対訳辞書（例：{"사재혁": "サ・ジェヒョク"}）
```

---

## 2. 生成フェーズ（辞書作り）

1. **抽出**： sampling した本文断片からAIが人名だけを列挙します（役職・地名・組織名・作者名は除外、2文字以上のみ）。
   - 韓国語は助詞・語尾を剥がした素形で取り出します（例：「사재혁이」→「사재혁」。「물이나」の「이나」は文法なので取らない）。
2. **名寄せ**：断片ごとの列挙を統合し、重複を1つにします。フルネームと短い呼び名は別人扱いで両方残します（例：フルネームとその呼び名）。
3. **命名**：各原文名に日本語読みを付けます。中国語は漢字優先、韓国語はカタカナ既定（漢字が自然な場合のみ漢字可）で作品内統一します。抽出時の素がある名前には人物メモ（40字以内の不変の性格・身分）を合成します。命名は弱いモデルでも完走できるよう60名ずつに割って送り、割れた表記スタイルは多数決（同数は先勝ち）で統一します。素を送ったのにメモ欠けの回は上限内で取り直し（最良の回を採用）、それでも空の時は訳語を温存して確定し警告ログを残します。

* **再開**：作業所に断片が残るため、中断時は未完了分から差分生成します。
* **部分確定**：確定的に失敗した断片だけ除いて統合します。一時的失敗（制限等）が混ざる場合は保留し、翻訳全体が待ちます。
* **文面変更時**：辞書指示文を変えても既存辞書は再利用されます。作り直す場合は `dictionary.json`（と `.dict_building`）を削除して再実行します。

## 3. 言語別の辞書方式

| 言語 | 方式 | 動作 |
|---|---|---|
| 中国語 | 書き込み式 | 本文中の名前に読みを `名前⟦読み⟧` と書き込み、訳文から剥がします（例：原文 `李云来了` → 送信時 `李云⟦李雲⟧来了`） |
| 韓国語・英語 | 対応表式 | 本文は無改変で、指示文に対応表を付けます（例は7章参照）。モデルが語形合わせをします |

中国語は語形が変わらないため書き込み式が壊れにくく、韓国語・英語は語形変化・同形衝突があるため対応表式にしています。

## 4. 探し方（章ごとの名簿絞り）

辞書登録名のうち「この章に出ている名前」だけを機械的に探します（AIに聞かず文字探しで行い、指示文の肥大化を防ぎます）。探し方は言語別です。

* **中国語：全文探し**（例：文中の `李云` に反応）
* **韓国語：文節先頭探し**（例：`이나가` の `이나` は人物として拾うが、`물이나`（水でも）の `이나` は文法なので拾わない）
* **英語：単語境界探し・大文字小文字区別**（例：`Mark came`・`John's book` は拾うが、`Market` の中の `Mark`・文中の助動詞 `will` は拾わない）

誤爆の実例と対策：

* `晩夏` の中の人名、`悩んでいた` の中の人名、フルネーム＋印の末尾が別人に見える分（例：フルネーム＋主語の印の末尾2文字が別人と一致）は拾いません。
* 最終判断（文法か人物か）はAIが行い、無関係な表行は無視してよい旨を指示しています。

---

## 5. 短形と許容読み

章内でフルネームと短い呼び名が混在し、モデルが短い方に寄せても別人ではないため、衝突のない短形だけ許容読みとして認めます。

* 動作例：フル `ジン・イェソ` に対し訳文が `イェソ` でも合格します。
* 対象は韓国語3文字名で訳が `・` 区切り2部の物に限ります（例：姓1字＋名2字 → 名2字と訳の後半）。
* 除外条件：章内に短形名の本人がいる時、同じ短形に別読みが2者ある時は不採用にします。
* 4文字以上の名前（複合姓・西洋名等）は対象外です。現行辞書の長名は西洋・幻想名で、下2文字短縮が言語的に誤りのため、あえて除外しています。

---

## 6. 検証（訳文の確かめ）

必須語（中国語＝全件、韓英＝長い名のみ）の日本語読みが訳文にあるか確かめます。許容読みのいずれかがあれば合格です。

* **1件許容**：必須語の欠けが1件までは合格にします（例：9件中8件でも通過）。2件以上欠けは不合格です。
* 不合格の記録例：`dict-mismatch: 名A,名B (残存7/9件)` ＝9件中7件あり・2件なし。
* 不合格時は次の指示文で再送し、全滅時のみ確定失敗（赤札は内容依存のみ、一時エラーでは作りません）。

---

## 7. 対応表の挿入位置

指示文ひな形の中の `[人物対応表挿入位置]` という行がある位置に表が混ざります（人名規則の隣推奨。始めと終わりが強く中間が落ちる位置バイアスのため）。

* 表がある章：指定行を表に置き換えます（`人名規則 → 人物対応表 → 出力制約` の順で届きます）。
* 表がない章：指定行を消します。
* 指定行のない文面：表を末尾に付けます（従来通り）。
* 小説本文には入りません（中国語の `⟦⟧` 書き込みとは別物です）。

表の1行の形（例）：`- 사재혁 → サ・ジェヒョク`

## 8. 推敲での対応表

推敲on時は保存の直前に磨き直しを1回だけ行います。送る入力文は `原文 → 初回訳文 → 人物対応表` の順です。

* 磨き文は初回と同じ物差しで確かめ、通れば採用します。不採用（不合格・制限）時は初回訳文を使わず、保存しないで未完了保留にします（次回再試行）。
* モデルは空欄＝翻訳と同じ経路、指定＝専用モデルで別経路（開始ログに `✨ 推敲専用モデル` と出ます）。試行は1回固定です。
* 大ファイルはかけらごとに磨きます（かけら単位の品質は上がりますが、章またぎの表記ゆれ・語尾の単調化までは直りません）。

## 9. ログの読み方

* `辞書添付: 8名（登録71名中・対応表）` ＝この章に付けた人数・登録総数・方式。
* `辞書添付: 0名（登録71名中・なし）` ＝該当者なし（正常）。
* `辞書添付: X名（…区切り衝突のため辞書なし）` ＝注釈記号が本文と被り辞書なし素通し（中国語のみ）。
* `品質チェック不合格 (dict-mismatch: 名A (残存10/11件)): プロンプト#3 (1/2)` ＝11件中10件あり・1件なしで次指示文へ。
* `✨ プロンプト#3 でのリトライに成功しました` ＝再送で合格し保存。
* `✨ 推敲で更新しました` ＝磨きの採用。`⚠️ 推敲不採用のため未完了として保留します (理由・次回再試行)` ＝磨きの不採用（保存せず次回へ。理由は初回と同じ物差し名）。
* `一時エラー/制限のため未完了として保留します` ＝赤札なしの持ち越し（次回再試行）。

## 10. よくある失敗と対処

* **フルネームと短形の混在で毎回落ちる**：短形が許容読み・1件許容でほぼ通ります（例：フル4回・短形単独3回の章）。
* **単発言及の人物で落ちる**：従属節の1回言及は落とされやすく、1件許容で通ります。2回連続の同一失敗は再送では直らない系統的原因なので、記録を見て対処します。
* **毎章ほぼ全滅する**：辞書方式と言語の組み合わせか、指示文の改変が原因のことが多いです。添付記録（注釈／対応表）と不合格理由を確認します。
* **成功訳に変なカタカナが混ざる**（例：文法のはずが人名カタカナ）：表の無関係行をモデルが適用した汚染です。探し方の除外が効いているか確認します。

## 11. 設定項目一覧

* 詳細設定の共通タブ：辞書on/off・辞書モデル・走査量・遅延・冷却。
* 詳細設定のプロンプト編集タブ：辞書指示文3通（抽出・名寄せ・命名、空欄＝既定文）。
* 詳細設定の共通タブ：推敲on/off・推敲指示文（空欄＝既定文）。
* 辞書ファイル（`dictionary.json`）は手編集せず、作り直す場合は削除して再実行します（人物メモ欠け等の作り直しも同様）。人物メモの素を送ったのにメモ0件で確定した時は、命名の再試行後に警告ログを残します。
