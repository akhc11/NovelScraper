# Google翻訳Web・バックグラウンド翻訳 実装プラン（簡易版）

最終更新: 2026-08-18  
状態: 計画のみ。実装は未着手。

## 1. 目的

選択フォルダ直下の `.txt` をGoogle翻訳Webで1ファイルずつ翻訳し、選択フォルダ直下に作る `翻訳完了_GOOGLE` へ同名で保存する。

```text
選択フォルダ/
├─ chapter_001.txt
├─ chapter_002.txt
└─ 翻訳完了_GOOGLE/
   ├─ chapter_001.txt
   └─ chapter_002.txt
```

アプリをホーム画面へ移動しても、既存のスクレイピングと同じく前景Serviceの通知を出したまま処理を継続する。

## 2. 初版で行うこと・行わないこと

### 行うこと

- Google翻訳Webだけを使用する。APIは使わない。
- 翻訳専用の非表示WebViewを1つ作る。
- 対象フォルダをSAFで選び、直下のtxtだけを処理する。
- `翻訳完了_GOOGLE` がなければ作る。
- 同名の出力ファイルがあれば、内容を比較せず必ずスキップする。
- 行単位を基本に長文を分割する。
- 翻訳と既存スクレイピングを同時に動かす。
- 開始、停止、現在ファイル、完了件数、失敗件数を表示する。

### 初版で行わないこと

- API、APIキー、Googleアカウント操作、CAPTCHA回避。
- OS終了後・強制停止後の自動再開。
- 出力内容のハッシュ比較、上書き確認、再翻訳判断。
- 文字コードの自動判定。初版はUTF-8だけを正式対応にする。
- 翻訳ジョブの複数同時実行。
- Google翻訳の画面構造を複数バージョン・複数言語で網羅すること。

OSや端末によりWebView・Serviceが止まった場合は、その時点で翻訳も停止する。次回は、すでに出力ファイルがあるものをスキップして最初から実行できればよい。

## 3. 最小構成

既存のスクレイピングと同じ役割分担にする。新しい大規模なService、DataStoreの再開管理、コマンド仲介層は作らない。

```text
ScrapingViewModel
  ├─ 既存 ScrapingTask 群
  └─ TranslationTask 1件

ScraperService
  └─ 既存どおり通知とWakeLockを維持

TranslationTask
  ├─ 非表示WebView 1つ
  ├─ Google翻訳への入力・結果取得・クリア
  └─ TranslationFileStoreでSAF保存
```

### 追加するファイル

- `TranslationTask.kt`: 翻訳全体の順番とWebView操作
- `TranslationFileStore.kt`: SAFの読込・出力フォルダ作成・保存
- `TextChunker.kt`: 行優先の分割
- `TranslationPanel.kt`: フォルダ、言語、開始・停止、進捗表示
- `TextChunkerTest.kt`: 分割規則のテスト

### 変更する既存ファイル

- `MainUiState.kt`: 翻訳の最低限の表示状態
- `ScrapingViewModel.kt`: `TranslationTask` の開始・停止とUI状態更新
- `MainScreen.kt`: フォルダ選択と翻訳パネル
- `HeaderToolbar.kt`: 翻訳ボタン
- `MainActivity.kt`: Serviceを動かす条件を「スクレイピング中または翻訳中」にする
- `ScraperService.kt`: 通知文に翻訳進捗を表示できるようにする

`ScrapingTask`、`ScrapingStateMachine`、既存のファイル保存処理は変更しない。

## 4. ユーザー操作

1. ユーザーが翻訳ボタンを押す。
2. 翻訳パネルで対象フォルダを選ぶ。
3. 翻訳元言語と翻訳先言語を選ぶ。初期値は「自動検出 → 日本語」とする。
4. 必要なら「Google翻訳を開く」で画面WebViewにGoogle翻訳を表示して確認する。
5. 開始を押す。
6. 通知に進捗を表示し、アプリを閉じても処理を継続する。
7. 停止を押すと、現在のファイル処理が終わるのを待たずに停止する。

バックグラウンド実行では画面WebViewを使えないため、実際の翻訳設定はパネルで選ぶ。画面上で開いたGoogle翻訳は確認用であり、翻訳処理そのものは専用WebViewで行う。

## 5. 翻訳処理

### 5.1 開始前

1. SAFフォルダの読込・書込権限を確認する。
2. `翻訳完了_GOOGLE` を取得し、なければ作成する。
3. 直下のtxtを列挙する。出力フォルダ内は対象外にする。
4. 出力フォルダに同名ファイルがある入力ファイルをスキップする。
5. 残りが0件なら「翻訳対象なし」と表示して終了する。
6. 前景Serviceを開始して通知を出す。
7. `TranslationTask` が専用WebViewでGoogle翻訳を開く。

### 5.2 1ファイルの処理

1. UTF-8としてファイルを読む。読めない場合は失敗として次のファイルへ進む。
2. 空ファイルなら、空の同名出力を作成して次へ進む。
3. 長文ならチャンクへ分割する。
4. チャンクをGoogle翻訳の原文欄へ入力する。
5. 翻訳結果が得られるまで待つ。
6. 結果を直接取得する。クリップボードは使わない。
7. Googleの原文クリアボタンを押し、原文欄が空になったことを確認する。
8. 全チャンクの結果を順に結合し、同名出力ファイルとして保存する。
9. 次のファイルへ進む。

Googleエラー、CAPTCHA、入力欄・結果欄・クリアボタンが見つからない場合は、その場で全体を停止する。推測で別のボタンを押さない。

## 6. Google翻訳WebView操作

`TranslationTask` 内に、Google翻訳の操作だけをまとめる。

- Google翻訳ページを読み込んだ後、入力欄・結果欄・クリアボタンがあるか確認する。
- 実機で確認済みのGoogle翻訳画面構造だけを初版の対象にする。
- 入力テキストはJSONエスケープしてJavaScriptへ渡す。文字列連結だけでJavaScriptを組み立てない。
- 入力後、原文欄に期待した文字列が入っていることを確認する。
- 結果欄が空でなく、短時間に連続して同じ内容なら翻訳完了とみなす。
- クリア失敗時は次のファイルへ進まない。
- 停止後に返ってきたJavaScript結果は、`isRunning == false` なら無視する。

固定の英語ラベルだけに依存しない。実機のGoogle翻訳WebViewで入力欄・結果欄・クリア操作を先に確認してから実装する。

## 7. 長文分割

### 基本

- Google翻訳Webで確認した安全な上限以下にする。
- まず行ごとに詰める。
- 次の行を加えると上限を超える場合、現在までを1チャンクとして確定する。
- 改行は元の行にだけ含め、次チャンクへ複製しない。

### 1行が長い場合

1行だけで上限を超える場合は、その行を次の優先順で分ける。

1. 空白・タブの直後
2. 文末記号の直後
3. 読点・カンマの直後
4. 文字境界

分割位置までを前チャンクに入れ、次チャンクはその直後から始める。同じ文字を2つのチャンクに入れない。

実装時に必ず次をテストする。

```text
chunks.joinToString("") == originalText
すべてのチャンク長 <= 上限
```

## 8. バックグラウンドと同時実行

### バックグラウンド

- 翻訳開始直後に、既存の `ScraperService` を前景Serviceとして開始する。
- Serviceが通知とWakeLockを維持する。
- `TranslationTask` は画面WebViewと別のWebViewを使うため、Activityが見えなくなっても動作を継続できる。
- Serviceまたはアプリのプロセスが終了した場合は翻訳も止まる。自動再開はしない。

### スクレイピングとの同時実行

- スクレイピングは既存の `ScrapingTask` WebViewを使用する。
- 翻訳は `TranslationTask` WebViewを使用する。
- WebViewが別なので、同時実行を許可する。
- 通知は1つにし、スクレイピング件数と翻訳進捗を表示する。
- Google翻訳を画面に表示したままヘッダー再生ボタンを押すとGoogle翻訳をスクレイピングしてしまうため、その場合だけ開始確認を出す。

## 9. 実装手順

### ステップ1: 最小の画面とフォルダ選択

1. 翻訳ボタンと翻訳パネルを追加する。
2. SAFフォルダ選択を追加する。
3. 翻訳元・翻訳先の選択を追加する。
4. 選択フォルダ名と開始・停止ボタンを表示する。

### ステップ2: ファイル処理

1. `TranslationFileStore` を追加する。
2. 直下のtxt列挙、`翻訳完了_GOOGLE` 作成、同名ファイルのスキップを実装する。
3. UTF-8読込とUTF-8保存を実装する。
4. 空ファイルの保存を実装する。

### ステップ3: Google翻訳の最小検証

1. `TranslationTask` を追加し、専用WebViewでGoogle翻訳を開く。
2. 入力欄・結果欄・クリアボタンを検出する。
3. 短いテスト文字列を1回だけ入力、取得、クリアする。
4. ここが実機で成功するまで、複数ファイル処理を追加しない。

### ステップ4: 1ファイル翻訳

1. 1つの短いUTF-8 txtを翻訳して保存する。
2. 失敗時に出力ファイルを作らないことを確認する。
3. 停止ボタンでWebView操作が止まることを確認する。

### ステップ5: 長文・複数ファイル・バックグラウンド

1. `TextChunker` を追加する。
2. 行優先分割と長い1行の分割を実装する。
3. 複数ファイルを順番に処理する。
4. `isTranslating` を前景Serviceの通知条件へ追加する。
5. ホーム画面移動後も処理が進むことを実機確認する。
6. スクレイピング1件と翻訳1件の同時実行を確認する。

## 10. テストと完了条件

### 最低限の自動テスト

- 行単位の分割
- 1行だけの超長文
- 改行、空行、絵文字での重複なし・欠落なし
- 同名出力ファイルのスキップ

### 実機確認

1. 短文1ファイル
2. 複数ファイル
3. 長文と長い1行
4. 出力済みファイルのスキップ
5. ホーム画面移動後の継続
6. 翻訳とスクレイピングの同時実行
7. Googleエラー・CAPTCHA時の停止

### 完了条件

- `翻訳完了_GOOGLE` に同名txtが保存される。
- 同名出力があれば必ずスキップする。
- 原文の重複送信・チャンクの上限超過がない。
- アプリをバックグラウンドへ移動しても、通常は翻訳が継続する。
- スクレイピングと翻訳を同時に実行しても互いに止まらない。
- `assembleDebug` と追加した分割テストが成功する。
- 既存のスクレイピング機能を壊していない。
