# handoff: langcache三重・二重生成の構造的修正

## 根本原因（データフロー・責務の不一致）
- 正本の所在が暗黙で、入出力の両方に読み書き経路があり得た（SSOT違反）。
- 旧計画の分離後も `outputDirUri` が常にnullで出力ピンが参照されず（デッド高速パス）、固定仕様が崩れていた。
- 旧入力配置の移行削除がなく、三重残骸が残り続けた。
- 互換名 `.lang_cache.txt` が末尾`.txt`のため翻訳対象列挙に混入し、二重翻訳・件数不一致を起こした（テストで `expected:1 was:2` として再現）。
- 同名保存時のSAF自動リネーム ` (1)` への収束処理が配置ごとに分散していた。

## 修正（シンプル・疎結合）
- 新規 `v2/engine/LangCacheStore.kt` を単一所有者化（正本=翻訳完了_LLM直下の1件のみ）。
  `load / save（冪等・ピン上書き禁止）/ sweepDuplicates / migrateFromInput / clearInputCaches / isCacheFileName` に集約。
  ファイル名リテラルは本番Kotlinではこの1件のみ。
- `LanguageDetectStage` は検出専用にし、永続化・読み取りを `LangCacheStore` へ委譲（API互換維持）。
- `RunEngine` は既存出力のピーク参照→検出、実行時はピン優先の `effectiveLang` を下流（プロンプト順・容量・ワーカー）に一貫使用、
  正本確定後に限り旧入力配置を削除。事前分割時は全サブ出力の確定後に親旧配置を掃除。
- 列挙混入の封鎖：`processFolder`/`partitionStage`後処理/出力既存走査でキャッシュ系を除外。
  `PreSplit` 再利用判定は `part_*.txt` に限定（キャッシュ混入を型で排除、engine依存なし）。
- 仕様書 `llm_translation_behavior.md` の配置図を出力正本のみに更新。

## 根拠（推測で実装しない）
- Android Data layerガイド：Repositoryが単一SSOTを定義し衝突解決はRepositoryのみ、他層はRepository経由。
- Offline-firstガイド：書き込みはsuspend・冪等・ローカル正。
- SAF公式：同名保存は ` (1)` 付与、DISPLAY_NAMEはプロバイダ依存 → 作成前find＋実名検証＋重複削除＋再検索、DocumentFile超過時はDocumentsContract直結（現行SafFileStoreを維持）。

## 検証
- `:app:testDebugUnitTest` フル270件パス（2026-09-10、レビュー指摘修正後も再パス）。
- 新規回帰3件：旧三重→単一移行、出力ピン優先・非上書き、同一出力内の正規一本化。
- 既存 `V2HermeticPipelineTest` の成果物件数はキャッシュ除外に修正し、正本存在アサートを追加（意図=翻訳4件の並行検証を維持。V2EngineTestの除外慣行と一致）。

# 追記：翻訳パイプラインの骨格単一化（単一骨格＋3役）

## 根本原因
- 再試行が2実装に乖離（汎用側は運転者単位、単体側は指示文単位で回数を数える）。
- 訳文保存が6箇所に散在し、書込失敗の扱いが経路ごとに別実装。
- 失敗の確定方針（内容依存の確定的失敗だけ `.failed`、回線・制限等の一時的失敗は保留）が3箇所に分散。
- `FailureKind.kt` 自身が「分组が各所に分散すると必ず乖離する」と宣言しており、方針の一元化は正本の要求に合致。

## 修正（振る舞い不変のリファクタ。依頼文の成形・応答の解釈は3役に残す）
- 骨格カーネル（`Translate.kt` 内）：`RetryBudget`（予算の有効範囲だけ呼出側が所有）＋ `callWithRetry`（唯一の再試行実装。待機式・停止検査・コスト上限を1箇所に）＋ `saveOutputText`（唯一の訳文保存。作成→書込を1工程）＋ `shouldPersistFailed`（唯一の確定方針述語）。
- 汎用再試行・単体翻訳の自前ループを撤去しカーネル利用へ。回数前提（運転者単位共有／指示文単位）は予算の置き場所で完全再現。
- 作業者側の保存3件・判定1件、束ね側の保存2件・判定1件、大ファイル側の保存1件・判定1件を全てカーネルに寄せた。`.failed` 書込自体は従来どおり単一書込口のまま。
- 裏付け：Template Method（骨格は基盤に、不変部と可変部の分離）／RetryTemplate（再試行方針オブジェクト）／Android Data layer（共通判定の単一真実）。

# 追記7：名前比較の廃止（内容 addressing 化）

## 今回の報告の解読
- 全ワーカー同時の `content mismatch, re-splitting` は、宣言書の名簿と一覧の表示名が食い違うプロバイダ体質によるもの。
- 名前文字列の比較は生成応答と一覧取得で乖離し得る（自前の `.lang_cache` 拡張子付与と同型）。しかも作り直しは出側の既訳まで消すため、毎回振り出しに戻り翻訳が終わらない。
- 対策：入塊は内容ハッシュで解決する（名前は opaque）。宣言書v2（塊ハッシュ＋完了台帳）。旧形式は移行受入れし、次回分割で自己修復する。
- 完了台帳は改変検出時のみ追記し、通常時の書込は増やさない。出側の使い回しは名簿→台帳実名→名簿の順で解決する。
- 保存層の自己診断 probe を開始時に追加し、癖（未反映・改変・置換非対応）を1行で記録する。利用者報告待ちにしない。
- 新層で2件検出（新規分の名寄せ解決漏れ、テスト前提の非現実性）。いずれも修正済み。
- フル285件パス。

## 原因特定（ログの消去法）
- 当該ログは開始→約1秒→保持で、中間（塊失敗・照合失敗・待機・例外）が一切ない。
- 旧実装で無言かつLLM送信前に到達可能な失敗は入出力場所の名寄せ再解決のみ（他は全てログあり）。
- よって作成直後の一覧未反映で場所解決が空振りし、無言で中断していたと特定。

## 修正
- 宣言書が名簿＋解決済み場所を一体で返す化（名寄せ再検索の廃止）。
- 大ファイル結果を理由＋進捗付きに変更し、無言中断を全廃。作業者は開始→結果（完成／保持＋理由＋進捗）を1対1で記録する。
- 回帰2件：場所盲目でも完走すること、保持に理由と進捗が載ること。

# 追記5：正直な訂正＋想定外を拾う層の新設

## 訂正：「機能は変わっていない」は誤りだった
正確には「翻訳結果の仕様（何を訳し何をもって成功・失敗とするか）は不変だが、異常系・再開系・保存手順の振る舞いは意図的に変えた」。完全列挙：
- 宣言書なし残骸は使い回さず作り直す／作業所に宣言書が新設／出力先に一時ファイルが現れる／ログ行の追加
- 照合不一致は従来成功扱いの保存を失敗にする／言語固定の優先順位の変更

## 新層 `V2ChunkResilienceTest`（例示テストの上に載せる）
- 故障モデルは実機の文書化された振る舞いから：古い一覧・表示名改変・短縮書込・置換非対応。固定シードで再現可能。新規依存なし。
- 不変条件：最終成果物は不在か新規実行と同一か（欠落公開の禁止）／故障停止＋再開は新規実行と同一（再開同値性）／不正宣言書は例外なく作り直し。
- 初回実行で1件検出：中断後再呼出しの前提誤り（成功時は作業所が消えるため直接再呼出しは非現実的）。テストを中断→再開の現実形に修正し、契約を KDoc に明文化（呼出側が作業所を用意する）。
- フル281件パス。
