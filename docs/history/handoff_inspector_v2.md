# 引き継ぎ状況 - インスペクター＆プレビュー機能 大幅強化 (handoff_inspector_v2.md)

## 1. 概要・背景
既存の要素インスペクターを「単一選択・単一設定」から「マルチ選択・常駐ツールバー」へ進化させ、さらに本文から不要な要素を除外できる「除外セレクタ（複数指定）」機能を実装する。また、テスト結果画面から直接除外設定を行える双方向連携を実現する。

## 2. 実装計画

### Phase 1: データ構造と基本ロジックの拡張
- `ScraperConfig` に `exclude: String` (カンマ区切り) を追加。
- `SelectorField` に `EXCLUDE` を追加。
- `ScrapingScriptBuilder.buildScrapingScript` を改良し、抽出前に `exclude` セレクタに一致する要素を削除する処理を追加。

### Phase 2: 常駐型インスペクター・ツールバー
- `buildInspectorScript` を刷新。
- WebView最前面に [Title] [Body] [Next] [Exclude] [Save] を持つフローティング操作パネルを表示。
- [Exclude] モードでは、要素をタップするたびにその場で非表示にし、セレクタを蓄積。
- [Save] で一括して Kotlin 側へ設定を送信。

### Phase 3: インタラクティブ・プレビュー (テスト実行)
- `ScrapingScriptBuilder` のテスト用出力に「セレクタ情報付き行データ」を追加。
- `DialogHelper.showTestResultDialog` を Compose UI ベースのカスタムダイアログへ刷新。
- テキストタップで WebView 側の該当要素へスクロール＆強調。
- テキスト横の「×」ボタンで、即座に `exclude` 設定へ追加。

## 3. 実装内容
- **データモデル拡張**: `ScraperConfig` に `exclude` を追加し、`ScrapingResult` にデバッグ用の行情報を持たせました。
- **マルチ・インスペクター・ツールバー**: WebView上部に常駐し、[タイトル][本文][次へ][除外]を切り替えながら連続設定できるUIをJavaScriptで実装しました。
- **除外ロジック**: スクレイピング抽出前に、指定されたセレクタに一致する要素をDOMから削除する機能を `ScrapingScriptBuilder` に組み込みました。
- **インタラクティブ・プレビュー**: テスト実行結果を Compose ダイアログ (`TestResultDialog`) に刷新し、本文の各行をタップするとWebView側の該当要素を強調表示、削除ボタンで即座に除外リストへ追加できるようにしました。

## 4. 完了の定義 (DoD) [済]

- [x] 除外セレクタに指定した要素が、実際のスクレイピング結果から消えている。
- [x] テスト結果画面の文字をタップして、該当要素のセレクタが特定できる。
- [x] テスト結果画面の「×」で除外リストが更新される。
