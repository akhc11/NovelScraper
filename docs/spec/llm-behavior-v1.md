## 1. 全体フロー

```text
[開始]
  → 使えるAPIキーなし → 中止（分割・辞書もしない）
  → フォルダ毎に以下を繰り返す
      → 必要モデル枠の枯渇あり → 全体中止（分割・辞書もしない）
      → [物理分割ON] 生ファイル毎に「分割 → 即サブフォルダ翻訳」
      → 出力一覧で全件翻訳済み → スキップ（言語・辞書・ワーカーなし）
      → 言語判定（.lang_cache 優先）
      → [辞書ON] 辞書生成（失敗 → フォルダスキップ）
      → ワーカー並列翻訳
```

## 2. 辞書生成

```text
[抽出] 範囲サンプリング → 並列バッチ抽出（.dict_building に退避）
  → 全件成功 → [マージ] → [レビュー] → dictionary.json 確定
  → 欠けあり＋確定的失敗のみ → 成功分で部分マージ → 同上
  → 欠けあり＋一時的失敗混じり → 保留（次回再開、翻訳スキップ）
```

## 3. ファイル翻訳の3経路

```text
小ファイル → 少数束ねてバッチ翻訳 → 失敗分のみ単体へ
大ファイル → チャンク分割 → 順次翻訳 → 結合（中断時は .parts_* 保持）
単体     → 1件ずつ翻訳
全経路：品質NG → 次プロンプト／次モデル → 全滅で .failed
```

## 4. 完了判定・再開
- 完了＝出力あり（`.failed` を含む）。0バイト出力は破損扱いで未完了・再処理＋警告
- 空の原文は空出力を作って完了扱い
- `.parts_*` の存在自体が中断シグナル。大ファイルは親に `.failed` を作らず `chunk_N.failed` のみ
- `.failed` は手動削除運用。自動再試行・自動消去なし。削除＝次回再試行
- 停止ボタン時は `.failed` を作らず中間状態を保持し、次回レジュームする

## 5. バッチ・チャンクの約束
- 小ファイルは枠内に収まる範囲で少数束ねる。部分成功は確定保存し、欠落・品質NG分のみ単体へ
- JSON Schemaは失敗時XMLへ自動劣化する。バッチ完走判定は閉じタグ
- チャンク2以降の文脈は直前訳文末尾のみ。先頭チャンクのみ直前ファイル原文末尾を使える
- 結合は全チャンク揃い時のみ。境界の空行増殖を抑える。結合成功後に作業所を掃除する
- 未解決の `chunk_N.failed` があると後続チャンクは停止する

## 6. 品質・サニタイズ
- 品質判定はかな率主軸＋言語別サイズ比。剥離順序は ```→前口上→後口上→完了マーカー検証
- APIパラメータはnullable透過（未指定は送らない）。thinking系の同時指定はしない

## 7. ローテーション・送信制御
- 1ワーカー1キー専有。ワーカーは開始をずらす。停止時はキーを解放し、セッション終了時にプールをリセットする
- 429はRPD（日次除外）とRPM（一時冷却・自動復活）を判別する。RPM疑いは同モデル再試行を優先する
- 全ワーカー共通の最低送信間隔ゲートがある（辞書生成は対象外）。疎通テストもゲートを1回消費する
- 排他クレームは取得→try/finally解放。全消去は使わない

## 8. 辞書
- 範囲は先頭／全編均等から選択。合計スキャン上限あり
- 抽出キャッシュは番号＋内容ハッシュで検証し、不一致のみ再取得する
- マージは複数回、レビューは少数回リトライする。レビュー失敗時はマージ結果で確定する
- 辞書確定時に作業所を掃除する。辞書必須のため未完成時はフォルダ翻訳をスキップし、トーストで知らせる

## 9. 言語・分割
- 言語は `.lang_cache` 優先、欠落・破損時は再検出して補完する。分割時は作品毎に判定する
- 分割済みは触らない。空ファイルは空1パート。失敗・停止・文字化け時は作りかけを破棄する
- 取込上限超・文字コード隔離は理由付きスキップする

## 10. 起動ガード・キー枯渇
- モデル0件・キー未設定では開始不可。モデル削除は最低1件残す
- 辞書必須（辞書なし翻訳はしない）。辞書が作れる間は全体を続け、辞書モデル枠
  または翻訳モデル枠の全滅で初めて全体を中止する。一時的失敗では止めない
- 枯渇管理は（キー×モデル）ペア単位。辞書検知の429もモデル名付きで共有する
- 中止時は進行中ファイルに `.failed` を作らない。分割だけが残って動くことはない
 （前提：キー分散ローテーションON）

## 11. 品質エラー・辞書失敗の扱い
- 品質エラー（生成停止・プロンプト拒否・セーフティ等）は全滅後に `.failed` を作る。
  設定エラーのみ全滅時は作らない
- 辞書の確定的失敗は即切り上げて除外し、1件以上の成功があれば部分マージする

## 12. モデル・パラメータ則
- 対応：`gemini-3.8-flash`、`gemini-3-flash-preview` ほか。temperature は未指定＝未送信が既定
- thinking可否は単一判定（3.7/3.8のminimal→medium正規化、Gemma系は送らず出さず）
- 効果のない設定は表示しない（表示＝変更が反映される）
